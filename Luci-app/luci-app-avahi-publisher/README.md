# luci-app-avahi-publisher

LuCI-приложение для публикации записей Bonjour/DNS-SD через Avahi для сервисов,
которые размещены на других устройствах локальной сети. Полезно, когда NAS,
принтер, Windows-ПК или иной хост предоставляет сервис, но сам не анонсирует его
по mDNS: приложение создаёт запись (например, `_smb._tcp`), и сервис появляется,
например, в разделе «Сеть» Finder на macOS.

Приложение публикует только метаданные обнаружения. Трафик SMB, SSH, HTTP и
других сервисов идёт напрямую от клиента к целевому хосту и не проксируется
через роутер.

## Возможности

- страница LuCI **Службы → Публикация сервисов Avahi**;
- несколько управляемых записей DNS-SD;
- шаблоны SMB, SSH, HTTP, HTTPS и RDP, а также произвольный тип сервиса;
- публикация для IPv4, IPv6 или обоих семейств адресов;
- необязательная статическая IPv4-запись для хостов, которые сами не публикуют
  mDNS-адрес (A-запись в `/etc/avahi/hosts`);
- проверка отображаемого имени, полного доменного имени хоста, типа сервиса,
  порта и IPv4-адреса;
- состояние Avahi, число включённых записей, сгенерированных файлов сервисов и
  опубликованных адресов;
- атомарная генерация с резервной копией и откатом при ошибке;
- управляются только `/etc/avahi/services/avahi-publisher-*.service` и
  помеченный блок в `/etc/avahi/hosts`; конфигурация DHCP, маршрутизации,
  межсетевого экрана, Samba и целевого хоста не изменяется.

## Требования

- OpenWrt или ImmortalWrt с LuCI (клиентский JS-интерфейс; проверяется на 24.10
  и 25.12);
- пакет `avahi-dbus-daemon` (предоставляет `/etc/init.d/avahi-daemon` и каталог
  `/etc/avahi/services`);
- `jshn` (backend использует `/usr/share/libubox/jshn.sh`).

Пакет содержит только скрипты, JavaScript, переводы и файлы конфигурации,
поэтому имеет архитектуру `all` и собирается в формате `apk` для 25.12.

## Установка

```sh
apk update
apk add luci-app-avahi-publisher
apk add luci-i18n-avahi-publisher-ru   # русский интерфейс
```

Либо установите собранный `.apk` из репозитория пакетов:

```sh
apk add --allow-untrusted /tmp/luci-app-avahi-publisher_*.apk
```

После установки выйдите из LuCI и войдите снова (или перезапустите rpcd:
`/etc/init.d/rpcd restart`), затем откройте
**Службы → Публикация сервисов Avahi**.

## Использование

Пример для SMB-сервера:

| Поле | Пример |
| --- | --- |
| Отображаемое имя | Офисный NAS |
| Целевой хост | `nas.local` |
| Целевой IPv4-адрес | `192.0.2.10` (необязательно) |
| Тип сервиса | `_smb._tcp` |
| Порт | `445` |
| Семейство адресов | IPv4 и IPv6 |

Если имя `nas.local` не разрешается у клиентов, заполните целевой IPv4-адрес:
приложение опубликует для него A-запись. После сохранения клиенты находят запись
через роутер и подключаются напрямую к целевому хосту.

## Файлы и принцип работы

- `/etc/config/avahi-publisher` — конфигурация UCI (conffile);
- `/usr/libexec/avahi-publisher` — backend: `apply`, `clean`, `status`;
- `/etc/init.d/avahi-publisher` — применение конфигурации при reload/start и
  очистка управляемых записей при stop;
- `/etc/avahi/services/avahi-publisher-*.service` — сгенерированные записи;
- `/etc/avahi/hosts` — управляемый блок с A-записями (маркеры
  `# BEGIN avahi-publisher` / `# END avahi-publisher`);
- `/var/run/avahi-publisher.generated` — число сгенерированных записей.

Сохранение конфигурации перезагружает управляемые записи Avahi; недоступность
целевого хоста не препятствует сохранению.

## Проверка

```sh
/usr/libexec/avahi-publisher status
/etc/init.d/avahi-daemon running
ubus call luci getFeatures   # приложение не регистрирует собственный ubus-объект
```

На macOS:

```sh
dns-sd -B _smb._tcp local.
dns-sd -L "Офисный NAS" _smb._tcp local.
```

## Отличия от upstream

- Убрана ручная сборка `zh-cn` `.lmo` в `Build/Prepare`: в OpenWrt 25.12 и в
  единой сборке этого репозитория переводы штатно собираются `luci.mk` в

  `zh_Hans` дополнен отсутствующими строками.
- `LUCI_TITLE`/`LUCI_DESCRIPTION` переведены на русский в стиле остальных
  пакетов репозитория; авторство и ссылка на upstream сохранены в Makefile.
